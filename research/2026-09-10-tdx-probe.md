## 3. 欄位表（`News` DTO，來自 OpenAPI schema 逐一核對，非猜測）

實測回傳（`Live/News/Highway`）與官方 schema 完全吻合，欄位為：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `NewsID` | string | 消息代碼 |
| `Language` | string | 語系（實測皆 `Zh_tw`） |
| `Title` | string | 消息標題 |
| `NewsCategory` | int | 消息類別：1=交管措施、2=事故、3=壅塞、4=施工、99=其他 |
| `Description` | string | 內容描述（自由文字） |
| `PublishTime` / `UpdateTime` / `StartTime` / `EndTime` | datetime | 時間戳 |
| `Department` / `SubAuthorityCode` | string | 選填，發布單位 |
| `NewsURL` / `AttachmentURL` | string | 選填 |

**`News` DTO 整份 schema 裡沒有任何座標或里程欄位**（沒有 `Position`／`PositionLat`／`PositionLon`／`Mileage`／`RoadName`／`RoadID`）。里程（如 `132K+300`）與路線名（如「台21線」）只以**自由文字**形式嵌在 `Title`／`Description` 裡，要抓座標/里程必須自己寫正則從文字解析，TDX 本身不提供結構化欄位——**這與 A6 章「公告本身不含座標」的結論一致，TDX 的 News 端點只是把同一份公路局公告轉成 JSON，沒有額外加值座標**。

## 4. 台21現行夜間管制有沒有出現在回應裡？

**明確答案：沒有出現（長期基礎規則完全查無），只有相關的加嚴施工公告部分出現。**

依 `research/2026-09-10-route-and-current-controls.md` §2.2，台21現行夜間管制是兩層規則：

1. **長期基礎規則**：台21線 110K+900（草坪頭）至145K+035（塔塔加），**每日17:30至翌日7:00全車種禁止通行、道路封閉**（2013年11月起實施至今）。
2. **當前施工加嚴規則**：132K+300和社二號明隧道工區，白天(8:00~17:00)每整點放行10分鐘。

實測比對 196 筆 `Live/News/Highway` 全量資料：

- 搜尋「塔塔加」「草坪頭」「17:30」「17時30分」→ **0 筆命中**。長期基礎的夜間封閉規則本身**完全沒有以獨立事件出現**在 TDX 回應裡。
- 132K+300 那筆加嚴施工公告**有出現**（`NewsID 67297`，`NewsCategory=4` 施工），但 TDX 版本的 `Description` 文字只提到白天「每日8時起至17時止…整點放行10分鐘」，**沒有覆述夜間17:00~隔日8:00封閉的部分**（官方原始公告頁有這段，TDX轉出的摘要文字被截短了）。

**結論：TDX 的 `Live/News` 系列是「臨時性施工/事故快訊」通報系統，不是「常態性交通管制規則」的資料源。台21最關鍵的長期夜間封閉規則，TDX 完全查無，必須另外爬公路局公告頁（如 `thbu2.thb.gov.tw` 或 `ali-nsa.net` 彙整頁）才能拿到，不能只靠 TDX。**

## 5. 對架構決策的建議

- TDX `Live/News/Highway` **可以用**，作為「近期施工/事故」的補充資料源（有 12+8 筆台18/台21相關施工中的公告，免費、結構化 JSON、每次呼叫即時），但：
  - **沒有座標/里程結構化欄位**，需自己寫正則從 `Title`/`Description` 解析 `K+xxx` 里程樁號字串，再配合 A6 的里程→座標轉換方案（省道里程坐標CSV）換算。
  - **不涵蓋常態性交通管制規則**（如台21夜間封閉），這類規則仍要靠爬公路局公告頁（A2）取得。
- 因此資料層應該是**兩條線並存**，不是「二選一」：TDX News 拿臨時性施工/事故快訊（省事、結構化好抓）＋ 公路局公告頁爬蟲拿常態性管制規則（如台21夜間封閉，這條非爬不可，TDX 沒有）。
